# Stream URL Error Explanation

## Error observed

The playback failure:

```text
Failed to resolve stream URL: The page needs to be reloaded.
```

is a **native Android plugin error**, not a frontend JavaScript error.

## Where it comes from

The call chain is:

1. `startPlayback()` in `client/assets/app.js`
2. `resolveStreamUrl()` in `client/assets/app.js`
3. `window.Capacitor.Plugins.LocalBackendPlugin.getStreamUrl(...)`
4. `LocalBackendPlugin.getStreamUrl(...)` in `android/app/src/main/java/com/monify/player/plugins/LocalBackendPlugin.java`
5. `StreamInfo.getInfo(ServiceList.YouTube, finalUrl)` from `NewPipeExtractor`

Inside `LocalBackendPlugin`, this code catches any exception:

```java
} catch (Exception e) {
    String msg = e.getMessage() != null ? e.getMessage() : e.getClass().getSimpleName();
    Log.e(TAG, "getStreamUrl failed: " + msg);
    call.reject("Failed to resolve stream URL: " + msg);
}
```

That means the string `"The page needs to be reloaded."` is **not generated by your app**. It is the exception message returned by the underlying extractor stack and then wrapped by:

```java
call.reject("Failed to resolve stream URL: " + msg);
```

## What the error actually means

This usually means `NewPipeExtractor` failed while parsing YouTube's response for that video URL.

In practice, this is typically one of these cases:

- YouTube changed the page/player response format and the extractor version no longer matches it.
- YouTube returned a transient anti-bot / challenge / consent / reload-style response instead of the expected stream metadata.
- The extractor got a response that implies the client session or page state is invalid and needs a refresh before metadata can be read.

## What it is not

It is probably **not** one of these:

- Capacitor bridge wiring problem
- Missing plugin registration
- Empty URL passed from JS
- HTML audio playback issue
- `NewPipeExtractor` initialization issue

Why:

- The plugin is clearly detected from JS.
- `getStreamUrl(...)` is successfully invoked.
- The plugin does not reject with `"NewPipeExtractor not initialized yet"`.
- The failure happens only when the extractor tries to resolve YouTube metadata.

## Most likely root cause in this project

Your Android app is using:

```gradle
implementation 'com.github.TeamNewPipe:NewPipeExtractor:v0.24.2'
```

That is an older extractor version. The most likely root cause is:

**YouTube changed something and `NewPipeExtractor v0.24.2` can no longer reliably parse the target page/response for this request.**

## Why the frontend shows this exact message

The frontend does not replace the native error. It logs and rethrows it:

```javascript
} catch (e) {
  console.error('[ERROR] LocalBackendPlugin getStreamUrl failed:', e);
  throw e;
}
```

Then `startPlayback()` catches it and reports generic playback failure:

```javascript
console.error('Playback failed:', error);
stopPlayback(true);
setPlayerStatus('Playback failed. Try another song.');
```

So the visible debug message is the native exception text propagated through Capacitor.

## Bottom line

The error is best understood as:

**"The Android YouTube extraction layer failed to parse or validate the YouTube page/response for this video, and the app is surfacing that upstream extractor message unchanged."**
